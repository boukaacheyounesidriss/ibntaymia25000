# ibn Taymia

اسمع لدي مشروع اريد اكماله معك و اعادة بناءه لاكمال تطوير ،، اريدك ان تتصل بقاعدة البيانات الخاصة بالمشروع و استخدام الملفات و البيانات و كنبذة ساعطيك التالي مع المرفق

# مشروع: نظام إداروم (IDAROM) - الإدارة الرقمية لثانوية تقي الدين ابن تيمية (قسنطينة، الجزائر)

## 1. الهوية وسياق المشروع
- المؤسسة: ثانوية تقي الدين ابن تيمية – قسنطينة (الجزائر).
- الهدف: منصة متكاملة لإدارة الحياة المدرسية تركز على: الحضور والغياب الآني، المسار القانوني الجزائري للتأديب والشطب، التواصل المباشر مع الأولياء (SMS / Telegram)، وتوفير أقصى درجات المرونة للأساتذة مع الحماية التامة من التزوير.
- التصميم: يدعم اللغة العربية والاتجاه (RTL First) بشكل كامل، مع دعم اللغتين الفرنسية والإنجليزية.

## 2. البنية التقنية (Tech Stack)
- الإطار البرمجي: TanStack Start v1 (React 19, SSR) مع Vite 7/8.
- التنسيق: Tailwind CSS v4 باستخدام متغيرات CSS دلالية (Semantic Tokens) ومكونات shadcn/ui.
- الواجهة الخلفية: Lovable Cloud مدمجة (قاعدة بيانات علائقية، مصادقة Auth، صلاحيات RLS، دوال خادمية createServerFn).
- المكتبات: TanStack Query للتخزين المؤقت، Lucide Icons للأيقونات، sonner للإشعارات.

## 3. ما تم إنجازه وبناؤه في النظام وقاعدة البيانات
1. محرك الحضور والغياب: منع تكرار الجلسات نهائياً لنفس القسم والتاريخ والحصة. حماية تسجيل الحضور خادمياً ومراعاة الأوقات الرسمية للحصص.
2. المسار القانوني الجزائري للغيابات: احتساب أيام الغياب غير المبررة طبقاً للقانون: الإشعار الأول (3 أيام)، الإشعار الثاني (6 أيام)، الإشعار الثالث (10 أيام)، والشطب عند 15 يوماً. الشطب هو إجراء حصري بقرار السيد مدير الثانوية فقط (struck_off)، ولا يتم حذف أي تلميذ من قاعدة البيانات حفاظاً على الأرشيف والمسار الدراسي.
3. تصاريح الدخول اليومية (Entry Permits): رقم تسلسلي يومي مغلق، مع تبرير الحصص المختارة فقط ومزامنتها مع العداد القانوني.
4. نظام إمضاء القسم ورمز PIN السري للأستاذ (آخر ما أُضيف في قاعدة البيانات): إضافة دوري "مسؤول القسم" (class_representative) و"نائب مسؤول القسم" (assistant_class_representative). حقل attendance_pin_hash مشفر للأستاذ مع منع الرموز البسيطة. آلية إمضاء الحضور من جهاز مسؤول القسم في قاعة الدرس: تقبل فقط في إطار الحصة الزمني (من 10 د قبلها إلى 20 د بعدها)، حظر لـ 15 دقيقة بعد 3 محاولات خاطئة، وتسجيل الإمضاء رسمياً باسم الأستاذ.
5. إدارة بيانات التلاميذ والاتصال: فصل هواتف الأولياء إلى father_phone و mother_phone، مع إمكانية إضافة حقول مخصصة لكل تلميذ. نظام إرسال SMS مباشر وتنبيهات داخلية وبوابة مخصصة لأولياء الأمور والتلاميذ.
6. مستكشف البيانات المركزي (/dashboard/data): واجهة للإدارة والمطور لتصفح، ترقيم، والبحث في السجلات وتعديل بيانات التلاميذ والجداول.
7. إعدادات الهوية المؤسسية: هوية موحدة بالموقع والوثائق المستخرجة تعتمد على سجل المؤسسة دون تثبيت نصوص برمجية جامدة.

## 4. المهمة المطلوبة منك الآن لإكمال البناء فوراً:
في قاعدة البيانات، بنية نظام رمز PIN للأستاذ ودور مسؤول القسم جاهزة ومكتملة، ولكن الواجهات البرمجية الثلاث التالية تنقصها التكملة والربط:
1. واجهة «تسجيل حضور القسم» (/dashboard/class-rep-attendance):
   - واجهة خفيفة وسريعة (Kiosk Mode) يفتحها مسؤول القسم أو نائبه في قاعة الدرس.
   - تعرض قائمة تلاميذ القسم للحصة الحالية لتحديد الغائبين والمتأخرين.
   - لوحة إدخال رقمية سريعة ومؤمنة ليوقع بها الأستاذ برمز PIN الخاص به، مع إغلاق فوري وقفل الشاشة بعد نجاح الإمضاء.
2. واجهة «إدارة مسؤولي الأقسام» (/dashboard/class-reps):
   - تمكن الإدارة من تعيين أو استبدال مسؤول القسم ونائبه لكل قسم دراسي ومنح الصلاحيات تلقائياً.
3. خانة «رمز PIN السريع» في الملف الشخصي للأستاذ:
   - تمكين الأستاذ من إنشاء أو تعديل رمز PIN الخاص به بأمان، مع إمكانية إعادة التعيين من طرف المدير عند النسيان.
4. تعبئة البيانات (Seeding):
   - لقد أرفقت لك ملفات الإكسل (التلاميذ، الأساتذة، البرامج الأسبوعية)؛ قم بقراءتها وتأكيد استيراد الـ 815 تلميذاً في أقسامهم الـ 23 وتثبيت قائمة الأساتذة في النظام.

## 5. قواعد وتعليمات صارمة للعمل:
- الحفاظ على كامل بنية الصلاحيات وقيود RLS.
- الالتزام بنظام TanStack Start v1 وعدم استخدام React Router أو أطر غير متوافقة.
- مراعاة العمل باللغة العربية (RTL) والألوان المتسقة مع النظام المدرسي.
- عدم حذف سجلات التلاميذ إطلاقاً (الاعتماد دائماً على حالة struck_off).
- التحقق من خلو البناء من أي أخطاء برمجية فور إتمام الصفحات.
